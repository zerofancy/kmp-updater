01 / 建议这一版做到哪里

建议首期：用户点击后开始下载，在应用内看到进度，下载成功后获得可使用的本地文件。继续保留原浏览器模式。暂不引入断点续传、跨进程恢复、后台保活或自动安装；它们不作为本次下载功能的前置条件。

本期交付

  • Android、Linux、Windows、macOS 使用同一下载状态与错误模型。
  • 流式写盘、已知 / 未知总大小进度、取消、手动重试。
  • 临时文件隔离、字节数核对、成功后交付本地文件。
  • Compose 下载界面、中英文文案、Android / 桌面示例。
  • 外链不能直接下载时，提供用户主动选择的浏览器回退。

作为后续独立能力

  • 断点续传：需要持久任务、Range 与资源版本验证。
  • 后台保活：Android 前台服务 / 系统下载任务，桌面守护任务。
  • 安装交接：Android 系统安装器、桌面安装包打开与重启。
  • 可信 SHA-256：需服务端发布、存储和查询协议一起补齐。

下载后的平台操作可由宿主接入。SDK 本期的成功条件是文件落盘，不报告安装完成；具体交接建议见第 08 节。

失败保留当前版本，展示可理解的错误，提供“重新下载”“浏览器下载”“关闭”。错误不会变成检查更新失败；取消不展示为失败。

04 / 复用现有两层，下载与检查各自管理

UpdateChecker→UpdateRelease→UpdateDownloader→DownloadedFile

updater 负责 HTTP、下载结果与平台文件存储；updater-compose 负责把检查状态和下载状态组合成 UI。自定义 UI 的宿主可直接调用下载器。

建议 API 形状

// 精简 API；完整公开声明见 DownloadModels.kt。
public data class DownloadProgress(
    public val downloadedBytes: Long,
    public val totalBytes: Long?,
)

public interface UpdateDownloader {
    public suspend fun download(
        release: UpdateRelease,
        onProgress: (DownloadProgress) -> Unit = {},
    ): DownloadResult
    public suspend fun delete(file: DownloadedFile)
    public suspend fun awaitIdle()
    public fun close()
}

// DownloadedFile 由 SDK 创建，包含绝对本地路径、文件名和实际大小。
// commonMain 不暴露 java.io.File；平台宿主可从本地路径读取文件。
public sealed interface DownloadResult {
    public data class Completed(public val file: DownloadedFile) : DownloadResult
    public data class Failed(public val error: DownloadError) : DownloadResult
}

// 平台工厂，均支持 DownloadOptions；可选注入独立 HttpClient。
createAndroidUpdateDownloader(context, options)
createDesktopUpdateDownloader(directory, options)

取消沿用协程 CancellationException，不包装为失败。进度回调不保证在 UI 线程执行；Compose 控制器将其转换成可观察状态。所有计数使用 Long，避免大文件溢出。

Compose 接入与旧版兼容

  • 保留现有 UpdateController(checker, browserOpener, scope) 与 rememberUpdateController(checker, browserOpener)，原调用继续使用浏览器模式。

  • 新增独立 downloadState: StateFlow<UpdateDownloadState>，包含 Idle、Downloading、Cancelling、Finalizing、Completed、Failed；原 UpdateUiState 的分支保留，不迫使旧宿主修改穷举判断。

  • Completed 状态是结果的可靠来源。宿主通过完成操作接收文件；不以可能错过的一次性事件作为唯一交付渠道，浏览器事件也不改成下载成功事件。

05 / 下载规则：流式写盘，显式处理重定向

  1. 单独配置网络。复用 Ktor 技术栈，下载使用独立客户端，不继承查询的 10 秒总超时。建议连接超时 15 秒、读空闲超时 60 秒、默认不限制总时长，均可配置；禁止自动重试。阻塞文件 IO 显式放到 IO dispatcher。
  2. 只接受完整 GET。首期不发 Range；正式文件只接受 HTTP 200。206 不追加到本地，204 / 空文件不能成为成功安装包。401 / 403 显示链接不可访问，可重新检查以取得当前发布信息；协议没有专门的地址刷新接口。
  3. 有限重定向。关闭客户端自动跟随，由 SDK 手动处理 301 / 302 / 303 / 307 / 308，最多 5 跳，每跳解析相对 Location 并复用 URL 安全规则。默认 HTTPS，可跨域到 CDN / 对象存储；拒绝 HTTPS 降级和非 HTTP(S) scheme。
  4. 隔离凭据。下载客户端不带业务 Cookie / Authorization，不把认证信息转发到外链，不在错误或日志中输出完整签名 URL。开发 HTTP 继续要求显式开启，Android 明文策略仍由宿主配置。
  5. 固定内存占用。分块读取 ByteReadChannel 写入文件，建议缓冲区 64 KiB；禁止把响应整体转为 ByteArray。进度最多约每 100 ms 更新一次，结束与失败立即更新。
  6. 长度与限额。请求 identity 编码，拒绝不能按原始文件字节核对的编码。已知 packageSize 时用作期望长度，否则使用合法 Content-Length；均未知则采用不确定进度。两者同时存在但不一致时失败，读取结束后再核对实际字节数。
  7. 限制异常响应。默认单文件上限建议 4 GiB，允许宿主按实际包大小调整；对已知大小提前检查，对未知大小在流式读取中持续检查。磁盘空间预检只作提示，实际写盘异常仍须处理。
  8. 识别下载页。拒绝明确 HTML / XHTML 或 JSON 错误响应，并通过有界前缀探测识别明显 HTML。普通二进制、octet-stream 或缺少 MIME 可以下载，不能只根据 URL 后缀判断。识别能力有限，不替代包格式或密码学验证。
429 保留合法 Retry-After，并在下载重试入口遵守冷却；没有有效值时默认 30 秒。网络断开、5xx、超时均交由用户手动重试，首期重试从 0 开始，不静默切到浏览器。

面向宿主的错误类型

Network、Timeout、Http、UnsafeUrl、TooManyRedirects、UnsupportedContent、EmptyFile、SizeMismatch、TooLarge、InsufficientSpace、FileIo、Busy、Closed。保留 HTTP 状态与冷却时间；不能确定原因的写盘异常归 FileIo，不误报磁盘已满。

06 / 文件存储与清理

平台建议存储宿主约定
AndroidfilesDir/kmp-updater/ 内部更新目录。只持有 applicationContext；下载无需存储权限。采用 filesDir 避免把完成文件完全依赖于可被回收的 cacheDir。
JVM 桌面工厂要求宿主传入更新根目录；SDK 只在自己的子目录内写入。宿主依据便携版、系统安装版和沙盒约束选取可写目录，示例展示保存路径。SDK 不假设所有桌面都有相同的 Downloads / cache 位置。
  • 每次下载创建独立任务子目录，先写 payload.part。正式文件名由受限软件名、versionCode、目标和安全扩展名生成，不直接采用展示名、URL 路径或 Content-Disposition 的任意文件名。
  • 已知包类型使用明确扩展名映射，例如 apk、AppImage、dmg、msi、exe、deb、rpm、zip；未知类型保存为 .bin 并保留包类型元数据，避免拼接任意路径。
  • 读取完成 → 关闭输出流 → 核对字节数 → 在同一目录重命名为正式文件 → 发布 Completed。重命名失败归 FileIo；不承诺所有文件系统都支持严格原子操作，不覆盖其他任务或宿主文件。
  • 取消 / 失败立即清理该任务临时文件；进程异常退出遗留的 .part 在下次初始化时清理。清理只限该 SDK 实例持有锁的任务目录，不能删除仍在下载的文件。
  • 成功文件不随弹窗关闭自动删除。提供显式 delete；初始化时可清理超过 7 天的 SDK 已完成文件，使用 SDK 标记与目录锁避免误删活动任务。宿主要长期保留时，应复制到自己的目录。
  • 首期不跨启动复用成功缓存，也不恢复残留任务。Completed 后再次访问前检查文件是否存在；下载器仅删除自己创建的文件，不接受任意路径删除。

07 / 并发、取消与生命周期

Available→Downloading→Finalizing→Completed

失败 → Failed → 手动重试；取消 → Cancelling → Available。下载 UI 子状态依附于当前 Available 版本，不能被旧任务覆盖。

  • 一个 downloader 实例同时只接受一个任务，直接 API 并发调用返回 Busy。控制器绑定当前 release 快照；取消、重新检查、更换配置时递增任务代次，旧回调和旧结果不能写入新状态。
  • 取消会传播到 HTTP 和写盘；有界清理完成后才允许重试。文件关闭与必要清理在 finally 中完成，必要时使用 NonCancellable 保证收尾。若下载器已完成正式文件但旧控制器结果被丢弃，回收该孤立文件，不把取消后的结果当作完成。
  • dismiss() / dispose() 取消本控制器任务；下载器 close() 可重复调用，标记关闭并发起在途下载取消，文件清理由下载任务收尾。awaitIdle() 挂起等待在途任务与清理结束；二者都不关闭宿主拥有的其他依赖。
  • 只在前台挂载 UpdateHost 的现有约定继续有效。因前后台切换而仅卸载 UpdateHost 不取消下载；任务在其 scope 存活期间尽力运行，回到前台展示最新状态。系统可以挂起或结束后台应用，本期不保证后台持续下载。
  • 默认 remember 控制器离开组合时取消任务；Android 配置变化若销毁控制器也会取消。需要跨旋转保留时，由宿主用 ViewModel 持有控制器 / scope；进程重启仍不恢复下载。
  • 宿主需要确定性释放时，调用 close() 后在协程中 awaitIdle()，再释放注入客户端。新配置使用新下载器实例和隔离任务目录；不得阻塞 UI 线程等待。强制进程退出可能中断清理，遗留文件由下次初始化回收。

08 / 下载后的平台交接

本期核心只承诺下载与本地文件交付。为了让宿主能继续完成更新，下载版 UpdateHost 预留完成操作：宿主提供按钮文案、动作与失败反馈；SDK 不默认执行下载文件。

平台 / 场景建议宿主行为实现边界
Android APK可另行接入“安装”，用户点击后打开系统安装界面。使用 FileProvider 的 content URI 和临时读权限，限定暴露更新目录；未知来源授权、REQUEST_INSTALL_PACKAGES 与安装结果处理属于安装适配器，不因下载而默认引入。
Windows / macOS优先提供“打开下载目录”；宿主可显式选择打开安装包。系统文件关联 / 目录打开能力需检查支持性，失败反馈回 UI；交接成功不等于更新安装成功。
Linux提供下载路径或“打开下载目录”，由宿主说明当前发行格式如何更新。AppImage 不自动 chmod / 替换运行文件；deb / rpm 不自行提权，压缩包不自动解压覆盖。
没有完成操作显示“下载完成”和保存位置，用户关闭后返回应用；宿主仍能从状态取得文件。Android 私有目录不是文件管理器通用下载目录。若产品要求用户自行安装，应同时接入安装交接，而不能仅提示用户去私有目录查找。
建议顺序：先验收下载，再按实际宿主需求增加 Android 安装 / 桌面目录操作。商店分发、受管理设备或自有安装器可以使用自己的完成操作，不把安装策略固定进下载内核。

09 / 实施拆分与验收条件

步骤主要修改完成标准
1. 下载内核updater/commonMain 新增下载模型、选项、HTTP 流程；Android / JVM 平台增加文件存储与工厂。下载结果与检查结果分离；可靠取消、关闭、重定向、限额和字节数核对。
2. Compose扩展 UpdateController；下载 UI / 文案独立文件；保留现有浏览器 API。完整展示已知 / 未知大小、取消 / 重试 / 完成；旧接入仍可使用浏览器模式。
3. 示例与 fixtureAndroid / 桌面示例增加下载器与保存位置；本地 fixture 从测试页面扩为真实二进制及慢速 / 异常端点。成功路径下载真实文件，不再只观察浏览器交接；更新 README 和接入示例。
4. 回归与实机核心 / Compose 测试；Android 与桌面真实网络、文件系统验证。验证旧检查 / 浏览器逻辑；先完成 Linux、Android 的实测，再分别记录 Windows / macOS 结果，未测平台不能标记已通过。

必要测试矩阵

  • 数据与网络：已知 / 未知长度、chunked、大文件流式写盘、长度过长 / 过短、空文件、超限、HTML 页面、Content-Encoding、401 / 403 / 429 / 5xx、超时、断网。
  • 重定向：同域 / 跨域、相对 Location、循环、超过 5 跳、缺失 Location、HTTPS 降级及非法 scheme；确认不转发敏感头。
  • 文件系统：不可写、磁盘不足、重命名失败、取消清理、异常退出残留、多个实例目录锁、成功文件被删除、文件名与路径隔离。
  • 状态与生命周期：双击只启动一次、取消后迟到回调、失败后重试、离开组合、后台返回、更换配置、close 幂等；无需 UI 即可使用核心。
  • 设备 / 视觉：Android minSdk 24 与现代设备；Linux、Windows、macOS 至少分别验证下载。长说明、小屏、大字体、键盘操作、下载中主线程响应和约束内存占用。
