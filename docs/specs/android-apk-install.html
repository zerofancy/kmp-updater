下载完成后，在 Android 上安装更新

Android 宿主在 Manifest 声明安装权限，再调用核心 API 或换用 Android Compose 入口，即可把已下载的 APK 交给设备安装流程。用户在 Android 界面确认覆盖安装。

交付范围 用户流程 公开 API Android 实现 Compose 接入 实施与验收

交付范围

  • 面向 Android 7.0（API 24）及以上，安装与当前宿主同包名、签名兼容、版本更高的完整单 APK。APK 可按设备 ABI 分发，但单个下载产物必须可独立安装。
  • updater 的 Android 变体提供安装和授权设置入口。updater-compose 提供可选的 AndroidUpdateHost，包含安装按钮、设置引导和本地错误提示。
  • 使用安装能力的宿主主动声明 REQUEST_INSTALL_PACKAGES。库 Manifest 合并私有 FileProvider，宿主无需自行配置 provider。
  • 首版的系统交接范围止于提交请求。静默安装、系统安装结果监听、重启应用、安装其他应用、AAB 和需要整组提交的 split APK 留待后续单独设计。

现有下载流程已经交付 DownloadResult.Completed.file。Android 使用内部存储，Compose 的通用完成动作返回布尔值。 应用内下载 spec · 当前接入说明 · 完成动作源码

用户流程

  1. 下载更新
  2. 点击「安装更新」
  3. 核对本地 APK
  4. Android 显示安装确认
场景用户看到的行为
下载完成保留版本和文件信息。安装模式下主操作为「安装更新」，次操作为「完成」。点击安装后显示「正在准备安装…」，合并重复点击。
Android 8.0 及以上未授权提示「请允许此应用安装未知应用，返回后再点安装更新」。用户可点「打开设置」，返回后用原 APK 再点「安装更新」。每次点击重新读取权限。拒绝授权或直接返回时，下载仍处于完成状态。
安装请求已交出Android 负责安装确认、取消与失败提示。宿主若恢复到原弹窗，可提示「安装请求已交给 Android」，并允许用户重新打开安装界面。原 APK 可复用。
APK 无效或已丢失保留对应的失败提示。文件消失或内容无效时，用户可关闭弹窗，再检查并重新下载。包名不符或版本过低时，提示用户需要当前应用的更新版本。
设置或安装界面无法打开保留下载结果和错误提示，用户可重试或关闭。设备限制可继续由 Android 设置或安装界面说明。

「已交出」的判定点是 Activity 启动调用正常返回。 Android 之后可能显示选择界面、拒绝安装、由用户取消或替换宿主进程。宿主下次启动时使用设备的实际已装版本。

宿主持有 Activity，SDK 只在本次调用期间使用。调用应绑定当前前台界面的生命周期，界面失活时取消尚未交接的准备任务。取消传播 CancellationException；已经发出的请求由 Android 继续处理。库错误仅返回枚举，避免暴露私有路径、文件 URI 或下载地址。

Android 实现

按系统版本授权

<!-- 启用安装能力的宿主 AndroidManifest.xml -->
<uses-permission android:name="android.permission.REQUEST_INSTALL_PACKAGES" />
  • API 26 及以上。 从自身 PackageInfo.requestedPermissions 检查宿主声明，再使用 canRequestPackageInstalls() 查询授权。授权为 false 时返回 PermissionRequired。用户主动打开设置时使用 ACTION_MANAGE_UNKNOWN_APP_SOURCES 和 package:<宿主 applicationId>，每次重新提交前复查实际状态。权限查询或启动被系统拒绝时返回可处理的错误。
  • API 24–25。 直接走 APK 交接，由系统安装流程处理设备的全局未知来源选项。安装授权设置入口在这些版本返回 Unsupported。

校验实际安装包

  1. 复用下载存储的任务校验。接受 Android SDK 内部完成文件对象，核对 filesDir/kmp-updater/ 下的任务目录、已完成标记、文件名和大小。拒绝临时文件、符号链接、目录穿越和宿主自制的文件对象。用任务锁协调准备、删除与自动清理。
  2. 用 PackageManager.getPackageArchiveInfo 读取包元数据。期望包名来自当前的 activity.packageName，服务端 UpdateRelease.packageName 是展示字段。安装预检比较 APK 与设备已装版本的实际 versionCode，更新检测继续使用现有服务协议。API 28 起使用 long version code，旧系统使用 versionCode.toLong()。
  3. 宿主发布时使用同一 applicationId 和兼容签名。Android 在正式安装时负责签名及签名轮换、split 完整性、系统版本和设备策略等校验。SDK 的归档预检只判断本地文件和包元数据。

下载 checksum 校验

服务端在 latest 中成对返回 checksumAlgorithm 与 checksumValue。SDK 解析 sha256 和 sha512 到 UpdateRelease.checksum。两项都缺失或为 JSON null 时视为未提供。声明不完整、格式无效或算法不支持时，查询返回 InvalidResponse。

Android 与 JVM 共用下载流程，在流式写盘时增量计算原始字节的摘要。摘要一致后才转正文件并返回 Completed。摘要不匹配返回 ChecksumMismatch 并清理临时文件。旧发布未提供摘要时依然可以下载和发起安装。APK 签名兼容性仍由 Android 在安装时检查。

授权读取并交接

  • Android AAR 自带专用 FileProvider 子类和路径资源。authority 为 ${applicationId}.kmp-updater.install，exported=false、grantUriPermissions=true，只映射 filesDir/kmp-updater/。KMP Android library 启用 androidResources，AndroidX Core 依赖放在 androidMain。
  • 用 setDataAndType 设置 content:// URI 和 application/vnd.android.package-archive，通过 ACTION_VIEW 与 FLAG_GRANT_READ_URI_PERMISSION 授予该 URI 的临时读取权限。从当前 Activity 直接调用 startActivity 并捕获 ActivityNotFoundException 和 SecurityException。由 Android 选择 APK handler，支持不同厂商的安装器，也避开 Android 11 起对预先查询匹配应用的限制。
  • 系统可能在启动调用返回后才打开文件。交接前在同一任务锁下记录持久的 24 小时保护期，再启动 Activity 并释放锁。自动清理按普通保留期和保护期两者较晚的到期时间处理。保护期间，显式 delete(file) 沿用下载器的忙错误并保留文件。保护按文件独立记录，覆盖进程重建，无需再复制一份 APK。
  • 启动明确失败时可恢复该任务之前的保护期限。无法确认请求是否已经发出时保留期限。关闭弹窗、切换前后台或销毁控制器均不立即删除该文件或主动撤销 URI 权限。过期文件沿用下次下载器初始化时的惰性清理。

Compose 接入

// Android 源集，在 MaterialTheme 内。
// 宿主在 Activity onResume / onPause 时更新 foreground。
val controller = rememberUpdateController(checker, browserOpener, downloader)
AndroidUpdateHost(
    controller = controller,
    activity = activity,
    foreground = foreground,
)
  • AndroidUpdateHost 沿用共享的更新与下载弹窗，仅在 Android APK 的完成态渲染安装动作。安装状态由这个入口内部维护，绑定当前 release 和文件。安装文案有中英文默认值，宿主可通过 installStrings 参数覆盖。
  • 宿主持续组合此入口，foreground=false 时只隐藏弹窗。回前台后可再次点击安装。用户拒绝授权、取消系统安装或关闭弹窗后，库保留原有的文件保留机制。若 Activity 重建，安装动作使用新的 Activity；需要保持下载状态时可继续由宿主 ViewModel 持有现有控制器。
  • 通用 UpdateHost 和 CompletedDownloadAction 保留当前签名和行为。Android 宿主主动换入口后才出现安装操作。已有 0.2.x 调用方可继续使用浏览器、纯下载或自定义完成动作，JVM 桌面仍使用通用入口。

实施与验收

  1. 先实现核心安装与设置入口、任务交接保留和 Android AAR 资源。保留 JVM 下载存储原行为，限制交接保护只影响 Android 中送去安装的文件。
  2. 复用共用弹窗，实现 Android Compose 入口。接到 sample-android，在 README 给出 Compose 与自定义 UI 两条接入路径。
  3. 保留现有合成下载 fixture，另用真实签名 APK 做安装 fixture。以同一 Android 示例 applicationId、同签名、较高 versionCode 构建目标包，由本地 fixture 服务发布。安装验收使用独立的软件标识，初始版本取示例应用的实际已装版本。
验收项目通过条件
下载 checksumSHA-256 与 SHA-512 摘要匹配时发布完成文件。同长度内容被修改时返回校验错误，清理临时文件。旧发布缺少摘要时可继续下载。
API 24 或 25从私有目录下载完整 APK 后可启动系统确认。设备禁用全局未知来源时由系统处理。
API 26+ 和当前 API覆盖首次未授权、打开设置但拒绝、允许后返回再点、取消安装后重试、确认安装。至少用一个新系统验证无包可见性查询时的真实 URI 交接。
覆盖结果确认后由宿主进程外通过 adb 或设备设置核对较高已装版本，重开后读取实际版本并确认示例应用数据仍保留。签名不兼容时系统拒绝，已装版本保持原值。
拒绝非法输入覆盖外部路径、符号链接、临时文件、文件消失或大小变化、损坏 APK、另一 applicationId、同版本与低版本。所有预检拒绝均不授予文件 URI。
异常与保留覆盖无安装处理程序、Manifest 未声明权限、Activity 销毁、连续点击、离开前台和设置页返回。模拟极短下载保留期，验证交接文件在保护期内避开清理和显式删除，重建进程后保护仍生效，过期后可清理。
发布制品与兼容从本地 Maven 发布制品构建独立 Android 消费方，核对 AAR 的 provider、路径 XML、依赖和按 applicationId 生成的 authority。核对安装权限来自启用安装的宿主 Manifest。跑原有下载、Compose 与 JVM 回归验证。

本地联调在 Android 7.0（API 24）与 Android 15（API 35）模拟器从 versionCode 5 覆盖升级到 6，重新读取已装版本并确认应用数据保留。API 35 另外验证未授权返回、授权后重试和取消安装后复用原 APK。
