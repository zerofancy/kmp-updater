更新弹窗显示新版本描述

用户发现新版本时，可在点击「前往下载」之前阅读该版本的更新内容。

01 范围02 发布与下发03 弹窗行为04 验收05 线上样本依据

01 / 范围

覆盖使用 https://zp.ntutn.top 检查更新的 Android 和 JVM 桌面宿主。每次弹窗展示精确命中的最新安装包所属分发的说明。同一分发的安装包共享说明。

当前仓库的核心 SDK 已解析说明，Android 和桌面共用的 UpdateHost 已展示说明。采用现有发布字段和检查更新接口。宿主使用默认弹窗时复用 UpdateHost，自绘弹窗时从 UpdateCheckResult.Available.release.description 取正文。

02 / 发布与下发

分发管理

  1. 发布者在新建或编辑分发时填写「纯文本版本」。正文直接面向用户，推荐一条改动一行。
  2. 同时维护 Markdown 时，可点「从Markdown版本同步」，再复核换行、列表和用词。两栏独立保存，同步后的内容随分发表单保存后生效。
  3. 为已发布版本补录时，编辑线上查询选中的 distributionId。补录说明可沿用现有包和版本号。

公开检查更新接口

GET /api/v1/updates?software=<内部名>&os=<系统>&arch=<架构>&packageType=<包类型>
Accept: application/json

用宿主实际配置的四项参数精确查询。HTTP 200 的 items[0].latest 同时返回包的 versionCode、versionName、distributionId 和该分发的两种说明。按匹配序列内最高 versionCode 选包，管理页上的分发发布时间或排序不决定匹配结果。检查更新接口公开访问，登录仅用于维护分发。

返回字段SDK 取值
descriptionPlainText有非空白字符串时用作正文。
descriptionMarkdown纯文本无内容时，用非空白 Markdown 原文作为正文。
两字段均无内容缺失、null、空串或全空白均视为无内容，弹窗省略说明区。

03 / 弹窗行为

  • 线上包的 versionCode 大于本地时，手动检查和静默检查共用同一描述展示规则。
  • 正文放在版本与可选包大小下方、浏览器提示上方。保留原换行，长内容可在正文区滚动，操作按钮在滚动区外。
  • 两种来源都按纯文本显示。Markdown 标记、HTML 片段和 URL 作为字符显示，点击「前往下载」才打开本次查询的下载链接。
  • 弹窗使用本次检查结果。发布者补录后，关闭已打开的弹窗并重新检查。若该包对本地仍是新版本，新弹窗显示补录后的说明。

04 / 验收

  1. 记录宿主实际使用的 SDK 构建和四项查询参数。查询线上接口，记录 HTTP 状态、目标版本、distributionId 与说明取值。
  2. 用配置相同、版本号低于线上返回值的宿主或样例检查更新。弹窗展示同一版本和同一份说明，中文和换行可读，长文可滚动。
  3. 在 Android 和 JVM 桌面各验证一次显示，分别使用匹配该平台的发布包。桌面可用本地 fixture 验证。正式接入使用自绘弹窗时，在实际宿主中验证其消费了同一个 release.description。
场景通过条件
纯文本与 Markdown 不同只显示纯文本。
仅有 Markdown按原文显示，保留换行。
两种说明均无内容弹窗正常展示版本和下载操作，省略说明区。
本地版本与线上相等或更高不出现新版本弹窗。

优先复用 UpdateCheckerTest 的字段取值用例和 Android 样例的 updateShowsPlainTextAndCanDismiss。仅 Markdown、双空与长文等输入可通过本地 fixture 覆盖。

定位未显示的原因

  • 请求未命中包或没有更新弹窗时，先核对四项参数和本地 versionCode。
  • HTTP 200 但缺少两个说明键时，核对线上部署的接口契约。键已返回但取值均为空时，按 distributionId 检查分发是否录入说明。
  • 线上有说明且返回了可更新版本时，核对宿主实际依赖版本、默认 UpdateHost 挂载和自绘弹窗的正文取值。

05 / 线上样本

2026-11-09，使用 awell / Android / ARM64 / apk 精确查询，HTTP 200 返回 AWell 1.0.1（versionCode=2，distributionId=8）。两个说明字段均有内容。公开 API 响应

在主界面底部新增手动检查更新。发现新版时可查看发布说明，并用浏览器下载 APK。最低支持 Android 7.0。

Android ARM64 真机使用本仓库样例，配置该序列与本地 versionCode=1，已确认直接从线上查询并显示 AWell 1.0.1 的正文。Android 样例的本地服务回归用例也通过，断言纯文本可见、Markdown 原文未出现。

macOS ARM64 的桌面 Compose 测试宿主使用本地 HTTP fixture 验证了三种情况：纯文本优先且长文可滚动、仅 Markdown 时保留原文和换行、说明为空时版本和操作仍可见。

验收覆盖 SDK 样例与桌面 Compose 测试宿主。分发编辑步骤依据服务端仓库。
