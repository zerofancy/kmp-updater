检测更新，提示用户，交给浏览器下载

01 / 目标与范围

用户点击“检查更新”或宿主发起启动检测 → SDK 查询对应安装变体 → 比较版本 → 有更新时展示提示 → 用户点击“前往下载” → 系统默认浏览器打开服务返回的下载地址。

初版包含

  • 协程式更新查询；严格匹配软件、系统、架构、包类型。
  • 基于现有 UpdateVersion.code: Long 的版本比较。
  • 最新版本、更新说明、可选包大小的 Material 3 弹窗。
  • 手动检测与宿主触发的静默检测两种交互策略。
  • 四个平台的浏览器打开适配、失败反馈及重试入口。
  • 统一错误模型、可注入网络与浏览器边界、接入示例。

后续版本范围

  • SDK 内下载、进度、断点续传、安装器、后台更新。
  • 文件校验、签名验证、差分、自动重启或回滚。
  • 强制更新、灰度、正式 / 预览通道、最低系统版本判断。
  • 忽略某一版本、持久化提醒间隔、定时轮询。
  • Markdown 渲染、累计更新日志、多包选择页。
  • iOS、Web、Kotlin/Native 桌面及 32 位架构。

初版不要求修改更新服务协议；服务地址由宿主传入，本文接入示例使用 https://zp.ntutn.top。SDK 不硬编码某个软件名或某个部署地址。

02 / 平台、架构与安装变体

运行平台KMP target / 协议 os架构常见 packageType（示例）
AndroidAndroid / AndroidARM64、X86_64apk
LinuxJVM / LinuxX86_64、ARM64appimage、deb、rpm、tar-gz
WindowsJVM / WindowsX86_64、ARM64exe、msi、zip
macOSJVM / MacOSARM64、X86_64dmg、pkg、zip

macOS 复用现有 JVM target，不新增 Kotlin/Native target。Android 保持当前工程 minSdk 24；SDK JVM 字节码保持当前 JVM 11 目标，实际 CMP 宿主运行时要求由其 Compose 版本决定。

目标解析规则

  • software、currentVersion、packageType 必须由宿主显式配置。版本来自构建元数据，包类型来自当前安装变体，不能按文件后缀或最大版本猜测。
  • 提供平台目标探测工厂：桌面按运行中 JVM 的 os.name / os.arch 识别，amd64、x86_64 → X86_64；aarch64、arm64 → ARM64。其他值返回 UnsupportedPlatform。
  • Android 使用当前进程位数与设备支持 ABI 共同判断；仅 32 位进程直接返回不支持，不因设备支持 ARM64 而选取 ARM64 包。
  • 自动探测反映运行环境，不能可靠推断原安装包。宿主可显式覆盖架构；Rosetta、Windows ARM 上的 x64 JVM 等场景默认沿用进程架构，不自动切换原生架构。
  • 包类型为开放标识，必须与服务端发布数据完全一致。exe-installer 与 exe-portable 等变体应分别配置；不在 apk、deb、dmg 等类型之间自动切换。
  • 当前服务仅支持两种架构，32 位 Android / x86 / ARMv7 不纳入初版，不退化为不带 arch 的宽查询。
一个更新序列 = (software, os, arch, packageType)。本地 versionCode 必须与该序列使用同一递增尺度。商店与侧载、不同 Linux 发行版等安装兼容性由宿主及发布方保证；服务不提供这些维度的判断。

以下为评审用 API 草案，完整构造器与平台工厂在实现时补齐。公共类型继续使用显式 API；现有 UpdateVersion 保持兼容。

data class UpdaterConfig(

    val currentVersion: UpdateVersion,
    val target: UpdateTarget,

    val allowInsecureHttp: Boolean = false,

interface UpdateChecker {
    suspend fun check(): UpdateCheckResult
}
sealed interface UpdateCheckResult {
    data class Available(val release: UpdateRelease) : UpdateCheckResult
    // 相等或服务版本更低均不升级；保留 latest 供宿主诊断。
    data class UpToDate(val latest: UpdateVersion) : UpdateCheckResult
    data object NoMatchingPackage : UpdateCheckResult
    data class Failed(val error: UpdateError) : UpdateCheckResult

interface BrowserOpener {
    suspend fun open(url: String): BrowserOpenResult
}
sealed interface BrowserOpenResult {
    data object Dispatched : BrowserOpenResult
    data class Failed(val reason: BrowserOpenError) : BrowserOpenResult
}

// Compose 模块：名称为拟议 API；状态由控制器以 StateFlow 暴露。
enum class CheckTrigger { Manual, Silent }
// rememberUpdateController(checker, browserOpener)
// controller.check(CheckTrigger.Manual)

UpdateRelease 至少包含目标序列、version: UpdateVersion、软件展示名、分发标题、包名、分发 / 包 ID、发布时间、下载 URL、可空字节数和两种可空更新说明。ID 保留为不透明字符串；版本和字节数使用 Long，DTO 与公共模型分离。

04 / 与 updater-server 的协议

精确查询

GET https://zp.ntutn.top/api/v1/updates
    ?software=<内部名>&os=Linux&arch=X86_64&packageType=appimage
Accept: application/json

只发送上述四个查询参数，各一次，统一经 URL 编码。currentVersionCode 不发给服务端；不使用登录、Cookie 或 Authorization。baseUrl 必须是无查询、片段和凭据的 HTTP(S) origin（可含端口与根路径 /），不支持部署子路径；请求路径固定为 /api/v1/updates。

参数本地校验
software[a-z0-9][a-z0-9._-]{0,99}
os / arch严格映射协议枚举；macOS 对应 MacOS，不可发送 macOS。
packageType[a-z0-9][a-z0-9-]{0,31}；初版 SDK 必填。
currentVersioncode > 0，name 非空；不自动 trim 或修改标识。

成功结果校验与比较

  1. HTTP 200 且为 JSON；query 四项与本次请求一致，items 恰好一项。
  2. 结果项的四个序列维度精确匹配，内外层 packageType 一致。任何空数组、多项、维度不符均为 InvalidResponse，不任选一项。
  3. versionCode 必须是十进制数字字符串，解析为 1…Long.MAX_VALUE；versionName 为非空字符串。不接受 JSON 数字、溢出、浮点、SemVer 排序或字典序比较。
  4. packageSize 为 null 或非负 Long 的十进制数字字符串，缺失按 null；"0" 保留为 0。版本 / URL 等关键字段缺失或格式错误时判为无效响应。
  5. 未知字段忽略；两种 description 缺失、null、空白均按无内容处理。发布时间按 RFC 3339 解析，ID 作为字符串保存；展示元数据缺失时用本地软件名 / 包类型回退，时间缺失或无效时省略显示。
  6. 校验下载 URL 后，比较 latest.code > current.code：大于返回 Available；相等或更低返回 UpToDate。低版本不触发降级，不跨序列比较。

服务按每个完整序列的最大 versionCode 选包，发布时间和分发标题不参与排序。通用包可以覆盖多个架构；精确查询仍只取一个目标。服务当前没有通道字段，beta 等字样不会被自动排除。

说明展示

初版优先将非空 descriptionPlainText 放入纯文本控件；否则将 descriptionMarkdown 原样作为纯文本展示；均无内容时隐藏说明区。不解释 HTML、不加载外部图片、不自动将说明中的链接变为可点击元素。保留换行，长内容在说明区滚动。仅展示所选分发的说明，不拼接跨版本历史。

线上只做了无副作用探测：2026-11-03，使用示例 software=kica 的精确查询返回 HTTP 404 / SOFTWARE_NOT_FOUND，说明公开路由可响应，但该标识不能用于当前生产正例。成功结构依据本地服务代码和测试；联调必须换成实际发布的软件及变体。

05 / 状态与用户交互

Idle→Checking→Available→OpeningBrowser→Idle
结果 / 事件手动检测 Manual静默检测 Silent
Checking非阻塞进度提示；宿主按钮可按状态禁用。不显示进度；状态仍可观察。
Available弹出更新提示；仅主动点击“前往下载”才打开浏览器。
UpToDate提示“当前已是最新版本”。低版本结果文案为“暂无可用更新”。无提示，回到 Idle。
NoMatchingPackage提示“暂无适用于当前安装版本的更新包”。无提示，暴露结果供诊断。
检测失败失败提示，提供“重试”“关闭”。不打扰用户；暴露错误；不后台自动重试。
暂不更新 / 返回键 / 外部点击关闭提示回到 Idle；不记录忽略版本。下一次显式检测仍可提示。
浏览器交接成功关闭弹窗回到 Idle，产生一次 BrowserDispatched 事件；不显示下载 / 安装成功。
浏览器打开失败保留该版本提示，显示“无法打开浏览器”，提供“重试打开”和可选择复制的完整下载地址。

静态交互示意；最终视觉遵循宿主 Material 3 主题。

  • 弹窗标题、当前 / 最新版本、更新说明、操作按钮必须可读。包大小未知时省略，已知时按 1024 进制格式化并使用 KiB / MiB / GiB。
  • 内容较长、小屏、系统大字体下仍可滚动且按钮可到达；支持桌面 Tab 导航、Enter 激活焦点按钮与 Esc 关闭。打开期间禁用重复确认，取消仍能关闭提示。
  • 用户离开页面 / 应用进入后台后不突然弹窗。宿主只在前台挂载 UpdateHost；待展示结果可保留在当前控制器内，恢复前台后展示。
  • 启动检测由宿主放入一次性生命周期逻辑，不在重组中触发。SDK 不自行监听启动、不轮询、不主动打开浏览器。

06 / 浏览器跳转与 URL 规则

平台默认实现失败行为
AndroidIntent.ACTION_VIEW + CATEGORY_BROWSABLE，使用应用 Context 时加 NEW_TASK；无 WebView。无处理 Activity、被系统拒绝等转换为结构化错误，不崩溃。
Linux优先 Desktop.browse；不支持或明确失败时调用 xdg-open。缺少图形会话 / 命令 / 默认处理程序时返回失败。
WindowsDesktop.browse，交由系统 URL 关联。不支持或调用抛错时返回失败；宿主可注入适配器。
macOS优先 Desktop.browse；不支持或明确失败时使用 /usr/bin/open。启动失败或命令返回非零时返回失败。

系统 URL 关联可能交给浏览器或已注册的链接处理应用，SDK 无法强制特定浏览器。成功仅表示系统接受打开请求；不能验证页面是否可达、文件是否下载或应用是否更新。

  • 查询地址与下载地址默认必须为绝对 HTTPS URL，host 非空、无用户凭据、无控制字符。下载地址可跨域（例如对象存储），不限制为更新服务器域名。
  • 开发环境通过 allowInsecureHttp=true 显式允许 HTTP；Android 明文访问所需宿主配置由示例说明。禁止 file、javascript、intent 等非 HTTP(S) scheme。
  • 查询不跟随 HTTP 重定向，3xx 映射为服务错误，防止请求自动降级到 HTTP。下载跳转由外部处理程序负责，SDK 不探测 HEAD、不跟踪其后续重定向。
  • 外部命令采用参数数组传 URL，禁止拼接 shell 命令；等待退出放在 IO 调度器，最多等待 5 秒，非零退出 / 超时返回失败。已经交接后的结果仍不能证明网页加载成功。
  • 打开前再次校验传入 URL；只使用当前展示版本的 URL，防止旧结果 / 多次点击串包。可注入 BrowserOpener 便于测试与宿主定制。

07 / 错误、并发与资源生命周期

场景核心结果处理规则
本地配置非法构造时 IllegalArgumentException属于宿主接入错误；平台工厂不支持时使用类型化失败，不发网络请求。
404 / NO_MATCHING_PACKAGENoMatchingPackage不等同于 UpToDate。
400 / INVALID_ARGUMENT
404 / SOFTWARE_NOT_FOUND		Failed(ServiceConfiguration)检查客户端配置或服务端软件标识；不原样自动重试。
409 / AMBIGUOUS_LATESTFailed(AmbiguousLatest)服务端修复发布数据；不随机选包。
429 / 500 / 503 / 其他 HTTPFailed(ServiceUnavailable / Http)保留 status 与可识别 error.code；用户显式重试。429 有合法 Retry-After 时保留重试时间并禁用过早重试，无效时默认 30 秒。
DNS / TLS / 断网 / 超时Failed(Network / Timeout)总查询超时默认 10 秒，可配置正 Duration；不阻塞主线程、不跳过 TLS 验证。
非 JSON / 错误 JSON / 无效字段Failed(InvalidResponse)代理 HTML、200 空数组、Long 溢出均不能解释为没有更新。
非法下载 URLFailed(UnsafeDownloadUrl)不展示可确认的更新操作，也不打开地址。
取消传播 CancellationException不包装成 Failed；结束加载状态，不弹检测失败。
  • 同一 Compose 控制器只允许一个查询。重复点击合并到当前任务，不排队；进行中的 Silent 查询收到 Manual 触发时提升为手动反馈策略。
  • 已有 Available 弹窗时重复检测只保留当前提示；关闭后可重新查询。OpeningBrowser 时禁用再次打开。控制器在销毁 / 配置变化时取消任务，旧结果不得覆盖新配置。
  • 核心 check() 是独立 suspend 调用，不持有 UI scope；不同调用方的并发由调用方管理。SDK 不创建 GlobalScope。
  • Compose 控制器由 composition scope 管理，业务状态用 StateFlow，瞬时通知只消费一次；取消后恢复可再次检测的状态。配置变化必须重新创建 checker / 控制器。
  • 默认工厂创建并拥有 HttpClient，提供可重复调用的 close()，取消在途请求并释放资源；宿主注入的 HttpClient 由宿主关闭。Android 适配器不长期持有 Activity。
  • 默认无持久缓存、后台重试、遥测和日志输出。错误可带诊断码，不直接把服务器 message 当用户文案；日志若由宿主开启，避免记录完整下载 URL 中的临时签名参数。
  • 响应读取上限 256 KiB，超出即 InvalidResponse 并取消读取。该上限覆盖当前服务两段各最多 10,000 字符的说明；避免无界读取意外响应。
